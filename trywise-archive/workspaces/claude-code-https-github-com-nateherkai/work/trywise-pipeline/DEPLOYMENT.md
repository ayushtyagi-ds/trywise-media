# Always-on deployment and cost containment — research, not a deployment

Research date: 2026-10-31. No account, subscription, billing, host, or automation has been created. The owner’s CAD $50/month ceiling may include their existing Google AI Pro subscription; confirm the actual price and tax before selecting paid services. The pipeline is a prototype; live Gemini, Buffer, Instagram and R2 connections are untested.

## Candidate architecture

Run one worker process with persistent private state, an independently reachable private reviewer interface, a public media store only for reviewed images, and Buffer for distribution. The concrete implementation still lacks a secure remote reviewer, reliable alerting, backups, fully connected approval-to-publish orchestration, and a tested provider connection. `review_server.py` is deliberately localhost-only, trusts its local browser, and explicitly must not be exposed to the public or reverse-proxied; hosting the current file on a server does not make it remotely accessible safely. This is a deployment design, not a ready-to-use recipe.

**Pilot:** run `worker.py` locally on the user’s Mac with a dedicated test API key and free-tier-only API access. This is not always-on; sleep, logout, outages, and reboots interrupt processing. Test actual consumption and output quality. Do not enable paid API billing, create accounts, expose assets or publish test posts until the owner understands the exact changes and costs.

**Possible hosted candidate after testing:** Railway Hobby plus one persistent volume, one worker replica, and no serverless idle sleep for an intended always-running process. Railway says Hobby is US$5/month including US$5 in resource usage, with additional resource consumption billed; RAM, CPU, network and volume rates are usage based. https://docs.railway.com/pricing ; https://docs.railway.com/pricing/plans

Store the queue SQLite database, job state, reviewed carousel files and Buffer ledger on the **same durable mounted volume**, backed up and restricted to that environment. Code/container filesystem is not a substitute. Run only one active worker against SQLite, avoid simultaneous writes from separate hosts, and configure process restarts and visible failure alerting. Railway’s volumes cannot be used with replicas, and redeployment with a volume has downtime. Its snapshots are per-project/environment and wiping a volume deletes its backups, so independent recoverability must be verified. https://docs.railway.com/volumes/reference ; https://docs.railway.com/volumes/backups

Do not blindly restore old queue/ledger data and restart publishing: remote posts could have succeeded after the backup and be duplicated. Stop sends after restoration, reconcile Buffer and Instagram against the ledger, and verify media remains available. Existing send paths require explicit digest-based confirmation and are not a complete unattended review/publish service.

**Free alternative:** scheduled GitHub Actions may stay within its included private-repository minutes, but scheduled runs may be delayed/dropped, and public scheduled workflows can be disabled after 60 days of inactivity. GitHub runners do not preserve the SQLite database or generated files automatically; implementing and validating private durable state, mutual exclusion, secure review and restoration is required. GitHub Actions artifacts or caches alone are not a transactional, durable database for the worker and send ledger. Treat this as batch scheduling, not an always-on server. https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows ; https://docs.github.com/en/billing/reference/product-usage-included

## Cost and ceiling

- Calculate **remaining CAD allowance = 50 - existing Gemini Pro charge if included - taxes/fees - fixed subscriptions - exchange reserve**. Unknown Gemini Pro cost currently prevents a defensible total. No assumption that free tiers are available on this account or will remain available.
- Railway’s subscription is US-dollar-denominated, counts against the CAD budget, and charges for resource consumption beyond included usage. Example only: a constantly running worker averaging 0.1 vCPU, 0.1 GB RAM and 1 GB stored for 30 days would imply about US$2 CPU + US$1 RAM + US$0.15 volume = US$3.15 usage, so the US$5 Hobby minimum applies before FX and tax. **These resource numbers are hypothetical, not a measurement or quote.** Network, backups, other services, or spikes add cost. Measure real usage before committing. https://docs.railway.com/pricing
- Railway says hard resource limits stop workloads when usage crosses the configured amount; compute and Railway Agent limits are separate. Provider docs indicate minimum configurable compute hard limit US$10; subscriptions, other providers, exchange rates and taxes still need separate accounting. Verify the owner’s actual account supports the feature. A stopped worker means missed processing and requires notification/recovery. https://docs.railway.com/pricing/cost-control ; https://docs.railway.com/cli/usage
- Gemini API and Google AI Pro are separate products. Prefer select free API-tier models with billing unlinked for the pilot, after verifying eligibility, quota, and data terms. The worker’s `--max-attempts-per-day` limits calls, **not CAD spend**, and cannot constrain another process using the same API key. Paid usage may be billed in USD. https://ai.google.dev/gemini-api/docs/pricing
- Google Cloud now documents project/service-scoped spend caps for eligible Gemini API usage, distinct from alerts-only budgets. Their enforcement is not instantaneous, overages are billed, and subscriptions are excluded. Availability and account permissions must be checked. A budget email is not a spending cap, and no cross-provider hard CAD cap exists from these controls. Leave a substantial reserve. https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps ; https://docs.cloud.google.com/billing/docs/how-to/budgets
- Cloudflare R2 Standard advertises 10 GB-month free, 1M Class A and 10M Class B operations, and free egress, but account setup requires an R2 subscription/checkout, usage beyond allowances is billed, and non-Standard storage has different treatment. Its r2.dev endpoint is for non-production development. Public images become accessible prior to social posting; screenshots and immutable media links are not secret. https://developers.cloudflare.com/r2/pricing/ ; https://developers.cloudflare.com/r2/get-started/ ; https://developers.cloudflare.com/r2/buckets/public-buckets/
- Buffer’s free plan and provider API allowances must be checked in the actual account, including carousel support and Instagram connection. Meta restriction may affect authorization; do not represent Buffer as a way to evade it.

## Required live acceptance gates

1. Confirm existing Gemini Pro charge, whether included in CAD 50, current taxes/FX and service prices; allocate a reserve. Keep paid billing disabled if no defensible cap is available.
2. Inspect and secure the Facebook/Meta account independently. Confirm a dedicated test Instagram account, then separately authorize a scheduler/provider account with appropriate scopes.
3. Measure one real API draft’s usage and cost, review sources and all claims, inspect all carousel slides at phone size, and log the exact result. Then validate daily call caps and actual provider-side quotas.
4. In a test workspace, prove the worker survives restarts with database and output intact, without a duplicated reservation; deliberately simulate feed, API, DNS and storage failure. Demonstrate alerting when stopped or over budget, and verify backup/restore through a separate recovery exercise.
5. Independently create and validate a secure remote reviewer; never expose the current local-only server as-is. Check that only approved content can proceed and that changes invalidate approval.
6. Authorize one explicitly reviewed test post, prove the public images match reviewed bytes, record the Buffer ID, observe actual Instagram publication, and simulate an ambiguous response without resending. Verify asset lifetime through publish time and confirm removal policy.
7. Reconcile after test failure, provider outage and restore; keep automation manual until every required check succeeds. Once live, watch the first several scheduled cycles and actual invoices. No growth or monetization result can be guaranteed.
